# 交付前自查（一条不过就补上再交）

**目标**
- [ ] 一句话说清要做什么、给谁用
- [ ] 「做成什么样算好」每一条都能检查，没有「更好看」「更科学」这种空话
- [ ] 写了真实的截止时间和收尾时段
- [ ] 估了预算，写了额度紧张时怎么降级
- [ ] 写了底线（不能碰的东西）
- [ ] 替用户补的默认值都标出来了
- [ ] 两个开关定好了：有人 / 无人值守，批量 / 小步

**过程**
- [ ] 有第 0 步：先做出能用的第一版
- [ ] 每轮动作固定、按顺序；批量模式下是「一口气改完整份清单再评」
- [ ] 「用」是真的操作，不是读代码推断
- [ ] 问题分级：致命 → 体验 → 打磨
- [ ] 写明连续干，不每轮停下等唤醒；有兜底唤醒
- [ ] 写明什么时候发布（默认最后一次性发布）
- [ ] 写明每轮先读任务说明文件

**检查迭代**
- [ ] 检查分成「只看过没过」「打分」「用户把关」三类
- [ ] 每项「过」都要求证据
- [ ] 给人用的东西有盲测（全新子代理只看屏幕提示）
- [ ] 主观质量的评审有：统一的尺子（配真实标杆）、定标卷、多人取平均、和最好版本并排比、一份清单给全、只有严重问题封顶、不许争分
- [ ] 有用户把关：定期发前后对比；用户挑中的版本定为基准
- [ ] 有记录文件，写明开工、每轮、用户新要求、停下时各记什么
- [ ] 停止条件六种都有：做完了、卡住了、没进展、来回摆、上限、用户暂停
- [ ] 卡住、没进展、来回摆的处理和「有人 / 无人值守」开关一致
- [ ] 「做完了」的条件可以逐条检查，并写明阶段性胜利不算收工
- [ ] 写了收尾要做的事

**红线**
- [ ] 花钱、删除、发布、对外发消息都写了怎么处理
- [ ] 写了「范围就是用户原话」
- [ ] 要求任何时候都留一个能用的版本
