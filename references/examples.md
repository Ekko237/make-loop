# 范例：改写前后对照（只是示范怎么补全，不是固定内容）

## 例 1：双人横版闯关游戏（抖音上看到的 loop）

**原文的问题**：结构对，但「检查」太靠 AI 自觉。
- 「直到没有更多意见」是自己说了算，容易第 2 轮就收工。
- 「关卡设计是否科学」没法检查。
- 没说「实际试玩」怎么玩，AI 可能只读代码。
- 没有记录，「同一问题连续两轮」没法判断。
- 意见不分轻重，可能在小问题上耗光 6 轮。

**改写后**：

```
你是这个任务的执行者，从头到尾自己干完，中途不用等我确认。汇报用中文大白话，只说结果。

【目标】
- 做一个浏览器里直接能玩的双人横版闯关射击游戏，原创卡通画风。
- 做成什么样算好：
  1. 两个人用两组键同时操作，同时按也互不干扰（默认：1P 用 WASD 移动、J 射击、K 跳；2P 用方向键移动、小键盘 1 射击、2 跳，要改告诉我）。
  2. 至少 3 关，节奏参考《超级玛丽》《雪人兄弟》：能打怪、有奖励道具、每关的地形和敌人不同。
  3. 新手 3 分钟内能通过第 1 关；后面每关比前一关难一点。
  4. 每段跳跃都跳得过去；每关有存档点；掉坑会死、能重生。
- 底线：纯前端，不接付费服务；画面和角色都是原创，不用别人的素材。

【过程】
第 0 步：做出能玩通 3 关的第一版，本地浏览器能打开。
之后每一轮：
1. 读 LOOP_BRIEF.md 和 PLAYTEST_LOG.md 里的待办。
2. 试玩：用浏览器自动按键把 3 关从头打到尾，两组键同时操作，每关截图或录屏。
3. 按【检查】逐条查，列出问题，分成致命（玩不了、卡死、键位冲突）、体验（手感差、难度跳变、看不清）、打磨（画面、音效、细节）三级。
4. 按上一次评审给的完整清单一口气改完：先修致命，再修体验，最后打磨。
5. 改完重新试玩，确认问题真没了、没弄坏别的。
6. 记一条到 PLAYTEST_LOG.md，一句话告诉我这轮改了什么。
7. 直接接着下一轮。

【检查迭代】
检查（每项「过」都要附截图或录屏位置）：
- 只看过没过：能开始、能通关、不卡死；同时按两组键互不干扰；怪能被打死、会扣血；人物和地面、墙、平台碰撞正常；掉坑会死、能重生；控制台无报错。
- 关卡：难度逐关上升；每段跳跃距离不超过最大跳跃距离；每关 1–3 分钟；奖励放在有一点风险的位置；第 1 关教会基本操作。
- 打分（1–10）：手感、难度曲线、关卡节奏、画面统一、打击反馈、想再玩一局。
- 独立评审：每轮开 2 个没参与制作的新子代理，各自试玩后按同一把尺子打分（10 分 = 能上应用商店推荐位的独立小游戏，8 分 = 完整好玩的小游戏，6 分 = 能玩但粗糙），取平均；同时和上一轮最好的版本并排比。评审一份给全：所有问题、每项怎么加 1 分。
- 让我把关：第 3 轮和收工前，把首关的前后对比截图或录屏发给我看，不用等我回复。

记录（PLAYTEST_LOG.md）：每轮「第 N 轮 · 发现的问题（分级）· 改了什么 · 验证结果和截图位置 · 分数」。

什么时候停：
- 做完了：上面目标 4 条全部有证据通过、独立评审各项 ≥ 8 分、连续 2 轮试玩挑不出致命和体验问题。说「可以了」，附上打开方式和 3 句总结。
- 卡住了：同一个问题连续 2 轮没解决 → 停下，告诉我问题出在哪、试过什么、建议怎么办（这个例子的原文就要求「告诉我问题在哪」，所以按有人值守处理）。
- 来回摆：同一处改回去又改回来第二次 → 选评分高的那版定下来，并在汇报里说明。
- 上限：最多 6 轮，到了就停，留一个能玩的版本。
- 我说「暂停」就收尾停下。

【红线】
- 不接付费服务；要生图先问我。
- 任何时候都留一个能玩的版本。
```
